A processor works with 0 and 1, but a knob has every position between its ends and a lamp every brightness between off and full, so a pin that only switches on and off cannot dim an LED or read a knob. Two tools close the gap: PWM (pulse width modulation) switches a pin so fast that the average acts as an in-between value, and the ADC (analog to digital converter) turns a voltage into a number. You also learn how the RP2040 lets you choose which pin does which job. The project is an LED dimmer: a knob sets the brightness, and the Pico prints the reading, the voltage and its own chip temperature. #GPIO #PWM #AnalogIO

<Card title="LED Brightness Controller" icon="star">

## GPIO Multiplexing

<InArticleAd />


On many microcontrollers each peripheral has fixed pins: the serial port is on these two and nowhere else, and two parts of a circuit that need the same pin force a new board. The RP2040 avoids most of these conflicts. Behind every GPIO (general purpose input/output) pin is a selector switch, a multiplexer, with one position for each peripheral that can use the pin. Only one position is active at a time; you set it with `gpio_set_function()`.

The positions are:

| Function Code | Peripheral | Example Use |
|---------------|-----------|-------------|
| GPIO_FUNC_SIO | Software I/O | Digital read/write (default) |
| GPIO_FUNC_SPI | SPI | Flash, displays, sensors |
| GPIO_FUNC_UART | UART | Serial console, GPS modules |
| GPIO_FUNC_I2C | I2C | OLED displays, IMUs, EEPROMs |
| GPIO_FUNC_PWM | PWM | LED dimming, motor control |
| GPIO_FUNC_PIO | PIO (Programmable I/O) | Custom protocols, WS2812 LEDs |
| GPIO_FUNC_USB | USB | VBUS detect, VBUS enable, overcurrent detect (D+/D- are dedicated pins, not GPIOs) |

The choice is wide but not free. Each signal of a peripheral can appear on a few pins only, listed in the RP2040 datasheet (Section 2.19.2). For example, the data output of SPI0 (MOSI) can be on GP3, GP7 or GP19, but not on GP0. The SDK does not warn you about a pin that cannot carry the signal; the peripheral simply stays silent.

```c
#include "pico/stdlib.h"
#include "hardware/gpio.h"

/* Configure GP15 as a PWM output */
gpio_set_function(15, GPIO_FUNC_PWM);

/* Configure GP0 and GP1 as UART0 TX and RX */
gpio_set_function(0, GPIO_FUNC_UART);
gpio_set_function(1, GPIO_FUNC_UART);

/* Configure GP4 and GP5 as I2C0 SDA and SCL */
gpio_set_function(4, GPIO_FUNC_I2C);
gpio_set_function(5, GPIO_FUNC_I2C);
```

With the selector on SIO (the default), your program drives the pin with `gpio_put()`, `gpio_get()` and `gpio_set_dir()`. On any other position the peripheral drives the pin, and those calls do nothing.

### Pull-Up and Pull-Down Resistors

An input pin with nothing connected reads 0 or 1 at random, and a button to GND leaves it so whenever it is not pressed. A pull-up resistor (about 50K to 80K ohms, inside the chip) holds the pin at 1 until the button pulls it to 0, as a spring holds a door shut until someone pushes it. A pull-down holds it at 0.

```c
/* Enable internal pull-up on GP14 (useful for a button to GND) */
gpio_pull_up(14);

/* Enable internal pull-down on GP14 */
gpio_pull_down(14);

/* Disable both pulls */
gpio_disable_pulls(14);
```

## PWM Slice Architecture

<InArticleAd />


A digital pin gives 0 V or 3.3 V and nothing between. To dim an LED, switch the pin on and off many times a second and vary the fraction of each period it is on: the duty cycle. The eye sees only the average, so at 25% the LED gets a quarter of full power. Hardware in the chip does the switching, so your code stays free.

The RP2040 has 8 PWM blocks, called slices, numbered 0 to 7. One slice is a clock divider, a 16-bit counter and two outputs, A and B. The two outputs share the counter, so they have the same frequency, but each has its own duty cycle.

```text
 ┌─────────┐   ┌────────────┐   ┌─────────────┐
 │  Clock  │   │   16-bit   ├──>│ compare with├──> pin A
 │ divider ├──>│  counter   │   │   level A   │
 │         │   │ 0 to wrap  │   ├─────────────┤
 └─────────┘   │            ├──>│ compare with├──> pin B
               └────────────┘   │   level B   │
                                └─────────────┘
```

Each pin belongs to one fixed slice and output, and neighbouring pins share a slice: GP0 is 0A, GP1 is 0B, GP2 is 1A, and so on to GP15, which is 7B; GP16 starts again at 0A. The SDK gives both numbers: `pwm_gpio_to_slice_num(gpio)` and `pwm_gpio_to_channel(gpio)`.

### How the Counter Works

The counter of a slice counts clock ticks from 0 up to a value you choose, **wrap**, then starts again at 0, so wrap sets the period. The output goes high when the counter restarts and low when it reaches a second value, the **level** of that output, so level sets how long the pin stays high.

- Frequency: $f_{\text{PWM}} = \dfrac{f_{\text{sys}}}{\text{wrap} + 1}$, where $f_{\text{sys}}$ is the system clock in Hz. The 1 is added because the counter also passes through 0.
- Duty cycle: $D = \dfrac{\text{level}}{\text{wrap} + 1}$, a fraction between 0 and 1.

The system clock of the Pico is 125 MHz. A wrap of 12499 gives 125,000,000 / 12,500 = 10 kHz. The largest value a 16-bit counter can hold is 65535, so the slowest PWM this formula can give is 125,000,000 / 65,536, about 1907 Hz.

### Clock Divider

Below 1907 Hz the counter must tick more slowly, so each slice has a clock divider (8 integer and 4 fractional bits: 1 to almost 256 in steps of 1/16). The frequency becomes:

```
PWM frequency = system_clock / (divider * (wrap + 1))
```

For example, a servo needs 50 Hz (a 20 ms period). With the largest wrap, 65535:

```
divider = 125000000 / (50 * 65536) = ~38.15
```

## PWM Configuration

<InArticleAd />


This code sets up a 1 kHz PWM on GP15. Three numbers decide everything: the divider, the wrap and the level.

```c
#include "hardware/pwm.h"

/* Get the slice and channel for GP15 */
uint slice = pwm_gpio_to_slice_num(15);    /* Slice 7 */
uint chan  = pwm_gpio_to_channel(15);       /* Channel B */

/* Set GP15 to PWM function */
gpio_set_function(15, GPIO_FUNC_PWM);

/* Configure the slice for 1 kHz.
   With divider = 1: 125000000 / (1 * (124999 + 1)) = 1000 Hz,
   but wrap = 124999 does not fit in 16 bits (maximum 65535).
   So use: divider = 2, wrap = 62499 -> 125000000 / (2 * 62500) = 1000 Hz */
pwm_set_clkdiv(slice, 2.0f);
pwm_set_wrap(slice, 62499);

/* Set duty cycle: 50% = 62500 / 2 = 31250 */
pwm_set_chan_level(slice, chan, 31250);

/* Enable the slice */
pwm_set_enabled(slice, true);
```

To change the duty cycle at runtime, call `pwm_set_chan_level()` with a new value between 0 (always off) and wrap+1 (always on).

### Frequency Calculation Summary

| Desired Freq | Divider | Wrap | Duty Resolution |
|-------------|---------|------|-----------------|
| 1 kHz | 2.0 | 62499 | 62500 steps |
| 10 kHz | 1.0 | 12499 | 12500 steps |
| 50 Hz (servo) | 38.15 | 65535 | 65536 steps |
| 100 kHz | 1.0 | 1249 | 1250 steps |

The last column is the price of a high frequency: the level is a whole number from 0 to wrap + 1, so a short period allows fewer duty cycles. At 100 kHz there are 1250 steps of brightness; at 1 kHz, 62500, far more than an LED needs.

## ADC Architecture

<InArticleAd />


An ADC measures a voltage and gives a whole number. The RP2040's ADC (a successive-approximation, or SAR, type) gives 12-bit numbers, 0 to 4095, up to 500,000 times a second, from 5 inputs (channels), one at a time:

| Channel | Input | Notes |
|---------|-------|-------|
| 0 | GP26 (ADC0) | External analog input |
| 1 | GP27 (ADC1) | External analog input |
| 2 | GP28 (ADC2) | External analog input |
| 3 | GP29 (ADC3) | On Pico: measures VSYS/3 |
| 4 | Internal | On-chip temperature sensor |

The ADC compares the input with a reference voltage, on the Pico the 3.3 V supply (pin ADC_VREF); 4095 means "equal to the reference". So one step, called one count, is:

```
Resolution = 3.3V / 4096 = 0.000806V per count (approximately 0.8 mV)
```

### Why 12 bits are not 12 bits of accuracy

A step of 0.8 mV is the resolution, the smallest change the number can show, not the accuracy: a ruler marked in millimetres does not measure to a millimetre if the ruler itself shakes. Two things shake the ADC:

- The reference is the 3.3 V supply, which comes from a switching regulator and carries its noise.
- The converter adds noise and small errors of its own. The RP2040 datasheet gives about 8.7 effective bits, not 12.

So a steady voltage gives readings that move by several counts, and a single reading can be trusted to about 8 mV. Averaging recovers some of the resolution: the average of 16 readings has a quarter of the random noise, which is 2 more effective bits.

### Round-Robin Mode

The ADC can step through several channels by itself. You give it a bitmask (one bit for each channel you want), and it converts them in turn and puts each result in a FIFO, a short queue that your program empties in the same order.

```c
#include "hardware/adc.h"

/* Initialize ADC */
adc_init();

/* Configure GP26 and GP27 as ADC inputs */
adc_gpio_init(26);
adc_gpio_init(27);

/* Enable round-robin on channels 0 and 1 */
adc_set_round_robin(0x03);  /* Bitmask: bit 0 = ch0, bit 1 = ch1 */

/* Enable FIFO, 1-sample threshold */
adc_fifo_setup(true, false, 1, false, false);

/* Start free-running conversions */
adc_run(true);
```

## On-Chip Temperature Sensor

<InArticleAd />


ADC channel 4 is a temperature sensor inside the chip. It gives 0.706 V at 27 degrees C, and its voltage falls by 1.721 mV for each degree warmer. The RP2040 datasheet turns this into a formula, with V the measured voltage in volts:

```
T (degrees C) = 27 - (V - 0.706) / 0.001721
```

To get V from the raw ADC reading:

```
V = raw_adc * (3.3 / 4096)
```

For example, a reading of 876 is 876 × 3.3 / 4096 = 0.7058 V, which gives 27 - (0.7058 - 0.706) / 0.001721 = 27.1 degrees C.

The sensor is not calibrated: expect an error of about plus or minus 2 degrees C. It measures the chip, which is warmer than the air around the board.

```c
/* Read the on-chip temperature */
adc_set_temp_sensor_enabled(true);
adc_select_input(4);
uint16_t raw = adc_read();

float voltage = raw * (3.3f / 4096.0f);
float temperature = 27.0f - (voltage - 0.706f) / 0.001721f;
```

## Circuit Connections

<InArticleAd />


The numbers in brackets are the board pin numbers.

```text
  ┌──────────────────────┐
  │  Raspberry Pi Pico   │
  │                      │
  │           3V3 (36)   ├─── Pot outer pin
  │                      │
  │   GP26 / ADC0 (31)   ├─── Pot middle pin
  │                      │
  │           GND (38)   ├─── Pot other outer pin
  │                      │
  │  GP15 / PWM 7B (20)  ├──[220R]──┤>├── GND
  │                      │           LED
  └──────────────────────┘
```

The potentiometer is a voltage divider between 3.3V and GND: its middle pin gives 0V to 3.3V on GP26 as you turn the knob. The LED is driven by PWM on GP15 (slice 7, output B): its long leg (the anode) goes to the 220 ohm current-limiting resistor, its short leg to GND.

:::note
On the Pico board only GP26, GP27 and GP28 can be ADC inputs. All other GPIOs are digital only. Do not also set an ADC pin as a digital output.
:::

## Complete Firmware

<InArticleAd />


The firmware repeats four actions five times a second: read the potentiometer, scale the reading from the ADC range (0 to 4095) to the PWM range (0 to 62500), write that level to the PWM slice, and print the values over USB serial.

```c
#include <stdio.h>
#include "pico/stdlib.h"
#include "hardware/adc.h"
#include "hardware/pwm.h"
#include "hardware/gpio.h"

/* Pin assignments */
#define POT_PIN     26      /* GP26 = ADC0 */
#define LED_PIN     15      /* GP15 = PWM Slice 7, Channel B */

/* PWM configuration for 1 kHz */
#define PWM_DIV     2.0f
#define PWM_WRAP    62499   /* 125 MHz / 2 / 62500 = 1 kHz */

static void pwm_init_led(void)
{
    gpio_set_function(LED_PIN, GPIO_FUNC_PWM);

    uint slice = pwm_gpio_to_slice_num(LED_PIN);
    pwm_set_clkdiv(slice, PWM_DIV);
    pwm_set_wrap(slice, PWM_WRAP);
    pwm_set_chan_level(slice, pwm_gpio_to_channel(LED_PIN), 0);
    pwm_set_enabled(slice, true);
}

static void pwm_set_duty(uint16_t level)
{
    uint slice = pwm_gpio_to_slice_num(LED_PIN);
    uint chan  = pwm_gpio_to_channel(LED_PIN);
    pwm_set_chan_level(slice, chan, level);
}

static float read_chip_temperature(void)
{
    adc_set_temp_sensor_enabled(true);
    adc_select_input(4);
    uint16_t raw = adc_read();
    float voltage = raw * (3.3f / 4096.0f);
    return 27.0f - (voltage - 0.706f) / 0.001721f;
}

int main(void)
{
    /* Initialize stdio over USB serial */
    stdio_init_all();

    /* Initialize ADC */
    adc_init();
    adc_gpio_init(POT_PIN);

    /* Initialize PWM for the LED */
    pwm_init_led();

    /* Wait for USB serial connection (optional, times out after 2s) */
    sleep_ms(2000);

    printf("LED Brightness Controller\n");
    printf("ADC -> PWM with temperature monitoring\n\n");

    while (1) {
        /* Read potentiometer (ADC channel 0) */
        adc_select_input(0);
        uint16_t pot_raw = adc_read();

        /* Convert to voltage */
        float pot_voltage = pot_raw * (3.3f / 4096.0f);

        /* Map 12-bit ADC (0-4095) to PWM level (0-62500) */
        uint32_t pwm_level = ((uint32_t)pot_raw * (PWM_WRAP + 1)) / 4096;
        pwm_set_duty((uint16_t)pwm_level);

        /* Calculate duty cycle percentage */
        float duty_pct = (pwm_level * 100.0f) / (PWM_WRAP + 1);

        /* Read chip temperature */
        float temp = read_chip_temperature();

        /* Print readings */
        printf("ADC: %4u | Voltage: %.3f V | Duty: %5.1f%% | Temp: %.1f C\n",
               pot_raw, pot_voltage, duty_pct, temp);

        sleep_ms(200);  /* Update at ~5 Hz */
    }

    return 0;
}
```

Compared with the USB text injector, two things change: the libraries are `hardware_adc` and `hardware_pwm` in place of TinyUSB, and `pico_enable_stdio_usb()` sends `printf()` output to the computer through USB CDC, a serial port carried over the USB cable.

   ```bash
   # Linux
   minicom -b 115200 -D /dev/ttyACM0

   # macOS
   screen /dev/cu.usbmodem* 115200

   # Or use the Arduino Serial Monitor, PuTTY, or any terminal program
   ```

6. Turn the knob. The LED brightness should change smoothly, and the serial output should show the ADC reading, voltage, duty cycle and temperature as they change.
</Steps>

## Exercises

<InArticleAd />


1. Add a second LED on GP14 (slice 7, channel A). It shares the slice with GP15, so both LEDs run at the same frequency. Give it the inverse duty cycle (`PWM_WRAP - pwm_level`) so that one LED brightens while the other dims.
2. Make a "breathing" LED that ignores the potentiometer: a loop ramps the duty cycle from 0 to full and back, in small steps with short delays. Compare a linear and an exponential ramp (the eye senses brightness logarithmically, so the exponential one looks smoother).
3. Average the ADC: take 16 consecutive readings of channel 0, sum them, and divide by 16 before mapping to PWM. Compare how steady the serial output is with and without averaging, mainly with the knob near the middle.
4. Log the temperature once per second, apart from the 5 Hz ADC loop. Track the minimum and maximum since power-on, and every 10 seconds print a line with the current, minimum and maximum temperatures.

## Summary

<InArticleAd />


A selector behind each GPIO pin connects it to one peripheral at a time, set with `gpio_set_function()`. PWM gives in-between values from a digital pin: in each of the 8 slices the divider and the wrap set the frequency, and the level of each output sets its duty cycle. Two pins of one slice always share a frequency. The ADC turns a voltage into a number from 0 to 4095, with a step of 0.8 mV, but noise makes single readings good to about 8 mV. The LED dimmer used all three.
