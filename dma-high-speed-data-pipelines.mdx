A sound recorder must take a sample 8,000 times a second and miss none: every missed sample is a click in the recording. If the processor fetches each sample itself, it can never be away longer than one sample period, 125 microseconds, yet saving to a flash chip takes milliseconds. DMA (direct memory access) removes the conflict: hardware that copies data without the processor. You tell it where to read, where to write and how many items, and it does the rest. In this lesson two DMA channels take turns to fill two buffers from a microphone, while the processor writes each full buffer to a flash chip. #DMA #AudioSampling #DataPipelines

## How DMA Works on RP2040

<InArticleAd />


Without DMA, the CPU moves every sample itself: stop the current work, read the ADC, store the value, return, like a worker who carries each box from a machine to the store by hand and can do nothing else. DMA is a conveyor belt between the two: the worker sets it up once and then deals only with full pallets.

The RP2040 has a DMA controller with 12 channels. One channel does one copying job between any two addresses: peripheral to memory, memory to peripheral, or memory to memory. In the RP2040 every peripheral register has an address, like a memory cell, so "read the ADC" is a read from an address. This is the pipeline you will build:

```text
 ┌──────────┐ one request ┌───────────────┐   ┌──────────┐
 │ ADC FIFO ├─────────────┤ DMA channel A ├──>│ Buffer A │
 │  8 kHz   │ per sample  │ DMA channel B ├──>│ Buffer B │
 └──────────┘             └───────────────┘   └────┬─────┘
                           A full: B starts        │ a full
                           B full: A starts        │ buffer
                                              ┌────▼─────┐
                                              │ CPU: to  │
                                              │ flash    │
                                              └──────────┘
```

### DMA Channel Registers

A copying job is described by four things: where from, where to, how many, and how. Each channel has one register for each:

| Register | Purpose |
|----------|---------|
| READ_ADDR | Source address. The DMA reads data from here. |
| WRITE_ADDR | Destination address. The DMA writes data here. |
| TRANS_COUNT | Number of transfers to perform before completion. |
| CTRL / CTRL_TRIG | Control register: data size, increment settings, DREQ source, chain target, IRQ enable. Writing CTRL_TRIG also starts the transfer. |

The control register holds several settings, called fields. You will not write these bits by hand: each SDK call in the code below sets one field. The fields this lesson uses (bit positions of the RP2040; the RP2350 of the Pico 2 moves several of them, and the same SDK calls still work):

| Field | Bits | Description |
|-------|------|-------------|
| DATA_SIZE | 3:2 | Transfer width: 0 = byte, 1 = halfword (16-bit), 2 = word (32-bit) |
| INCR_READ | 4 | If set, increment READ_ADDR after each transfer |
| INCR_WRITE | 5 | If set, increment WRITE_ADDR after each transfer |
| TREQ_SEL | 20:15 | Transfer request signal (DREQ) that paces the channel |
| CHAIN_TO | 14:11 | Channel number to trigger when this channel completes |
| IRQ_QUIET | 21 | If clear, raise an interrupt when transfer completes |

### Transfer Request Signals (DREQ)

Left alone, a channel copies as fast as the bus allows, millions of items a second. The ADC makes only 8,000 samples a second, so an unpaced channel would read the same old sample again and again: it must wait for the peripheral. Each peripheral has a DREQ (data request) signal that says "I have an item ready" (or, for an output, "I have room for one"). The TREQ_SEL field chooses which DREQ the channel obeys, and the channel moves one item per request.

Some DREQ numbers of the RP2040:

| DREQ Value | Signal | Typical Use |
|------------|--------|-------------|
| 0 | DREQ_PIO0_TX0 | PIO0 state machine 0 TX FIFO |
| 8 | DREQ_PIO1_TX0 | PIO1 state machine 0 TX FIFO |
| 16 | DREQ_SPI0_TX | SPI0 transmit FIFO |
| 17 | DREQ_SPI0_RX | SPI0 receive FIFO |
| 18 | DREQ_SPI1_TX | SPI1 transmit FIFO |
| 19 | DREQ_SPI1_RX | SPI1 receive FIFO |
| 36 | DREQ_ADC | ADC FIFO has data ready |
| 0x3F | DREQ_FORCE | Unpaced (transfer as fast as possible) |

This lesson uses DREQ_ADC: each time the ADC puts a result in its FIFO, it raises this request, and the DMA moves exactly one sample.

### Pacing Timers

Some jobs have no peripheral to set the rate. For these the DMA block has four pacing timers (0 to 3), each usable as a DREQ: you write a numerator and a denominator to its register, and the timer gives requests at `(sys_clk * numerator) / denominator` Hz.

This lesson does not use them: the ADC's own clock divider (the `DIV` register) sets the time between conversions, so DREQ_ADC arrives exactly when a new sample is ready.

## ADC with DMA Pacing

<InArticleAd />


In free-running mode the ADC converts again and again and puts each result into a FIFO, a queue with room for 4 samples. While the FIFO holds at least one sample, the ADC raises DREQ_ADC, and a DMA channel that obeys it takes one sample out per request, so the FIFO never fills.

### ADC Clock Divider

The sample rate must be exact, or the recording plays back at the wrong pitch. The ADC has a 48 MHz clock and needs 96 cycles for one conversion, so its highest rate is 48,000,000 / 96 = 500 kHz. With a clock divider, the ADC starts one conversion every (1 + divider) cycles. For 8 kHz:

```
divider = 48,000,000 / 8000 - 1 = 6000 - 1 = 5999
```

`adc_set_clkdiv(5999.0f)` starts one conversion every 6000 clock cycles: one sample every 125 microseconds. A divider below 95 has no effect, because a conversion cannot take less than 96 cycles.

### ADC FIFO Configuration

`adc_fifo_setup()` switches the FIFO on and tells the ADC to raise DREQ_ADC:

```c
adc_fifo_setup(
    true,   // Enable FIFO
    true,   // Enable DMA requests (assert DREQ_ADC when FIFO not empty)
    1,      // DREQ threshold: assert when at least 1 sample in FIFO
    false,  // Do not report conversion errors in FIFO
    false   // Do not reduce samples to 8-bit (keep full 12-bit)
);
```

Now the two addresses. Every sample comes from the same place, the ADC FIFO register at `&adc_hw->fifo`, so the read address stays fixed. Every sample goes to the next free place of a buffer in RAM, so the write address moves forward (increments) after each transfer. A sample has 12 bits, so each transfer is 16 bits wide.

```c
// Minimal ADC + DMA setup (single channel, no chaining yet)
#define SAMPLE_COUNT 1024

uint16_t sample_buffer[SAMPLE_COUNT];

int dma_chan = dma_claim_unused_channel(true);
dma_channel_config cfg = dma_channel_get_default_config(dma_chan);

channel_config_set_transfer_data_size(&cfg, DMA_SIZE_16);  // 16-bit transfers
channel_config_set_read_increment(&cfg, false);             // Fixed read address (ADC FIFO)
channel_config_set_write_increment(&cfg, true);             // Increment through buffer
channel_config_set_dreq(&cfg, DREQ_ADC);                    // Paced by ADC

dma_channel_configure(
    dma_chan,
    &cfg,
    sample_buffer,       // Write address (destination)
    &adc_hw->fifo,       // Read address (source)
    SAMPLE_COUNT,        // Number of transfers
    false                // Do not start yet
);
```

After `dma_channel_start(dma_chan)` and `adc_run(true)`, the ADC converts at 8 kHz and the DMA fills `sample_buffer` with 1024 samples while the CPU is free. The CPU can ask `dma_channel_is_busy(dma_chan)`, or wait for the interrupt (a signal that makes the processor run a piece of your code) that the channel raises when it finishes.

## Ping-Pong Double Buffering

<InArticleAd />


One buffer is not enough for a continuous recording: when it is full, the CPU must save it and restart the DMA, and every sample that arrives in that gap is lost. The answer is two buffers and two channels that take turns, like two buckets under a tap: while you empty one, the other fills.

### How Channel Chaining Works

The change from one channel to the other must not depend on the CPU, or samples are lost again. Each channel therefore has a `chain_to` field: when the channel has done all its transfers, the hardware starts the channel named there. Channel A names B, and B names A:

<Steps>
1. Channel A starts, filling Buffer A from the ADC FIFO.
2. Channel A finishes its 1024 transfers, raises an interrupt, and starts Channel B through `chain_to`.
3. Channel B fills Buffer B from the next sample on. No sample is lost, because the hardware makes the change.
4. While Channel B fills, the CPU writes the full Buffer A to flash.
5. Channel B finishes, raises an interrupt, and starts Channel A again.
6. The cycle repeats until the CPU stops both channels.
</Steps>

At 8 kHz a buffer of 1024 samples fills in 128 ms. The CPU has that long to save the other one:

```text
 time, ms    0        128       256       384
 DMA fills   ├── A ───┼─── B ───┼─── A ───┼─── B ──
 CPU saves            ├─ A ─┤   ├─ B ─┤   ├─ A ─┤
```

### Configuring the Ping-Pong Pair

```c
#define BUF_SIZE 1024

uint16_t buf_a[BUF_SIZE];
uint16_t buf_b[BUF_SIZE];

int chan_a = dma_claim_unused_channel(true);
int chan_b = dma_claim_unused_channel(true);

// Configure Channel A
dma_channel_config cfg_a = dma_channel_get_default_config(chan_a);
channel_config_set_transfer_data_size(&cfg_a, DMA_SIZE_16);
channel_config_set_read_increment(&cfg_a, false);
channel_config_set_write_increment(&cfg_a, true);
channel_config_set_dreq(&cfg_a, DREQ_ADC);
channel_config_set_chain_to(&cfg_a, chan_b);   // When done, trigger Channel B

dma_channel_configure(chan_a, &cfg_a,
    buf_a,             // Write to Buffer A
    &adc_hw->fifo,     // Read from ADC FIFO
    BUF_SIZE,          // Transfer count
    false              // Don't start yet
);

// Configure Channel B
dma_channel_config cfg_b = dma_channel_get_default_config(chan_b);
channel_config_set_transfer_data_size(&cfg_b, DMA_SIZE_16);
channel_config_set_read_increment(&cfg_b, false);
channel_config_set_write_increment(&cfg_b, true);
channel_config_set_dreq(&cfg_b, DREQ_ADC);
channel_config_set_chain_to(&cfg_b, chan_a);   // When done, trigger Channel A

dma_channel_configure(chan_b, &cfg_b,
    buf_b,             // Write to Buffer B
    &adc_hw->fifo,     // Read from ADC FIFO
    BUF_SIZE,          // Transfer count
    false              // Don't start yet
);
```

One detail decides whether this works. A channel started again through the chain reloads its transfer count but not its write address, which stays where the last turn ended: on its second turn Channel A would write past the end of `buf_a` and destroy other data. So the interrupt handler below points each channel back to the start of its buffer as soon as it finishes. This is safe, because the other channel is then the one running.

### DMA Interrupts

Both channels raise an interrupt when they finish, so the CPU knows which buffer is full:

```c
// Enable IRQ0 for both channels
dma_channel_set_irq0_enabled(chan_a, true);
dma_channel_set_irq0_enabled(chan_b, true);

irq_set_exclusive_handler(DMA_IRQ_0, dma_irq_handler);
irq_set_enabled(DMA_IRQ_0, true);
```

The interrupt handler checks which channel completed and sets a flag:

```c
volatile int buffer_ready = -1;  // -1 = none, 0 = buf_a ready, 1 = buf_b ready

void dma_irq_handler(void) {
    if (dma_hw->ints0 & (1u << chan_a)) {
        dma_hw->ints0 = 1u << chan_a;  // Clear interrupt
        dma_channel_set_write_addr(chan_a, buf_a, false);  // Rewind for next turn
        buffer_ready = 0;              // Buffer A is complete
    }
    if (dma_hw->ints0 & (1u << chan_b)) {
        dma_hw->ints0 = 1u << chan_b;  // Clear interrupt
        dma_channel_set_write_addr(chan_b, buf_b, false);  // Rewind for next turn
        buffer_ready = 1;              // Buffer B is complete
    }
}
```

## SPI Flash Driver

<InArticleAd />


The samples must go somewhere that keeps them without power: the W25Q32, a 4 MB flash memory chip with an SPI interface (a four-wire serial bus), usable up to 80 MHz. The recorder needs three operations: sector erase, page program (write) and read.

### W25Q32 Command Reference

| Command | Opcode | Description |
|---------|--------|-------------|
| Write Enable | 0x06 | Must be sent before every program or erase |
| Page Program | 0x02 | Write up to 256 bytes to a page |
| Read Data | 0x03 | Read continuous bytes starting at an address |
| Sector Erase | 0x20 | Erase 4 KB sector (sets all bits to 1) |
| Read Status Register 1 | 0x05 | Bit 0 (BUSY) indicates operation in progress |
| Chip Erase | 0xC7 | Erase the entire chip (takes several seconds) |

### Flash Constraints

Flash memory is not written like RAM, and two rules shape the recorder:

- You can write only to erased memory. An erased byte is 0xFF, and a write can only change bits from 1 to 0.
- Erasing works on a whole 4 KB sector at a time and is slow (about 45 ms, at worst 400 ms). Writing works on a page of at most 256 bytes (about 0.7 ms, at worst 3 ms).

So the recorder erases each sector before it writes into it, and writes in pages of 256 bytes.

### Minimal SPI Flash Driver

```c
// Pin definitions for SPI flash (using SPI1)
#define FLASH_SPI       spi1
#define FLASH_SCK       10
#define FLASH_MOSI      11
#define FLASH_MISO      12
#define FLASH_CS        13

// W25Q commands
#define W25Q_CMD_WRITE_ENABLE   0x06
#define W25Q_CMD_PAGE_PROGRAM   0x02
#define W25Q_CMD_READ_DATA      0x03
#define W25Q_CMD_SECTOR_ERASE   0x20
#define W25Q_CMD_READ_STATUS    0x05
#define W25Q_CMD_CHIP_ERASE     0xC7

static inline void flash_cs_select(void) {
    gpio_put(FLASH_CS, 0);
}

static inline void flash_cs_deselect(void) {
    gpio_put(FLASH_CS, 1);
}

void flash_spi_init(void) {
    spi_init(FLASH_SPI, 10 * 1000 * 1000);  // 10 MHz
    gpio_set_function(FLASH_SCK, GPIO_FUNC_SPI);
    gpio_set_function(FLASH_MOSI, GPIO_FUNC_SPI);
    gpio_set_function(FLASH_MISO, GPIO_FUNC_SPI);

    gpio_init(FLASH_CS);
    gpio_set_dir(FLASH_CS, GPIO_OUT);
    gpio_put(FLASH_CS, 1);  // Deselect
}

void flash_wait_busy(void) {
    uint8_t cmd = W25Q_CMD_READ_STATUS;
    uint8_t status;
    do {
        flash_cs_select();
        spi_write_blocking(FLASH_SPI, &cmd, 1);
        spi_read_blocking(FLASH_SPI, 0, &status, 1);
        flash_cs_deselect();
    } while (status & 0x01);  // Bit 0 = BUSY
}

void flash_write_enable(void) {
    uint8_t cmd = W25Q_CMD_WRITE_ENABLE;
    flash_cs_select();
    spi_write_blocking(FLASH_SPI, &cmd, 1);
    flash_cs_deselect();
}

void flash_sector_erase(uint32_t addr) {
    flash_write_enable();
    uint8_t cmd[4] = {
        W25Q_CMD_SECTOR_ERASE,
        (addr >> 16) & 0xFF,
        (addr >> 8) & 0xFF,
        addr & 0xFF
    };
    flash_cs_select();
    spi_write_blocking(FLASH_SPI, cmd, 4);
    flash_cs_deselect();
    flash_wait_busy();  // Sector erase takes ~45 ms typical
}

void flash_page_program(uint32_t addr, const uint8_t *data, size_t len) {
    if (len > 256) len = 256;  // Page size limit
    flash_write_enable();
    uint8_t cmd[4] = {
        W25Q_CMD_PAGE_PROGRAM,
        (addr >> 16) & 0xFF,
        (addr >> 8) & 0xFF,
        addr & 0xFF
    };
    flash_cs_select();
    spi_write_blocking(FLASH_SPI, cmd, 4);
    spi_write_blocking(FLASH_SPI, data, len);
    flash_cs_deselect();
    flash_wait_busy();  // Page program takes ~0.7 ms typical
}

void flash_read(uint32_t addr, uint8_t *data, size_t len) {
    uint8_t cmd[4] = {
        W25Q_CMD_READ_DATA,
        (addr >> 16) & 0xFF,
        (addr >> 8) & 0xFF,
        addr & 0xFF
    };
    flash_cs_select();
    spi_write_blocking(FLASH_SPI, cmd, 4);
    spi_read_blocking(FLASH_SPI, 0, data, len);
    flash_cs_deselect();
}

void flash_chip_erase(void) {
    flash_write_enable();
    uint8_t cmd = W25Q_CMD_CHIP_ERASE;
    flash_cs_select();
    spi_write_blocking(FLASH_SPI, &cmd, 1);
    flash_cs_deselect();
    flash_wait_busy();  // Full chip erase takes ~10-25 seconds
}
```

:::note
The minimal driver above uses GP10-GP13 for illustration. The complete project below uses GP12-GP15 to avoid conflicts with other peripherals. Adjust the pin definitions to match your wiring.
:::

The write and erase functions call `flash_wait_busy()`, which keeps the CPU waiting until the flash chip has finished. This waiting is why the project needs DMA: the samples keep arriving meanwhile. One buffer is 2048 bytes, eight pages: 8 × 0.7 ms, about 6 ms. A sector is two buffers, so every second buffer also needs an erase of about 45 ms first. Both fit in the 128 ms the other buffer takes to fill.

## Complete Project Code

<InArticleAd />


This is the full source of the audio sampler: the ADC, the two DMA channels, the flash driver and the PWM playback in one program.

```c
// audio_sampler.c
// Audio recorder using DMA ping-pong buffering with ADC and SPI flash storage

#include <stdio.h>
#include <string.h>
#include "pico/stdlib.h"
#include "hardware/dma.h"
#include "hardware/adc.h"
#include "hardware/spi.h"
#include "hardware/pwm.h"
#include "hardware/irq.h"
#include "hardware/gpio.h"

// -------------------------------------------------------
// Pin Definitions
// -------------------------------------------------------
#define MIC_PIN         26      // ADC0 input (microphone)
#define BUTTON_PIN      10      // Record start/stop button
#define PWM_PIN         18      // PWM audio output
#define LED_PIN         25      // Onboard LED (recording indicator)

// SPI Flash Pins (SPI1)
#define FLASH_SPI       spi1
#define FLASH_SCK_PIN   14
#define FLASH_MOSI_PIN  15
#define FLASH_MISO_PIN  12
#define FLASH_CS_PIN    13

// -------------------------------------------------------
// Audio Parameters
// -------------------------------------------------------
#define SAMPLE_RATE     8000
#define BUF_SIZE        1024            // Samples per buffer
#define BUF_BYTES       (BUF_SIZE * 2)  // Bytes per buffer (16-bit samples)

// Flash storage parameters
#define FLASH_MAX_ADDR      0x400000    // 4 MB total
#define FLASH_SECTOR_SIZE   4096
#define FLASH_PAGE_SIZE     256

// W25Q command opcodes
#define CMD_WRITE_ENABLE    0x06
#define CMD_PAGE_PROGRAM    0x02
#define CMD_READ_DATA       0x03
#define CMD_SECTOR_ERASE    0x20
#define CMD_READ_STATUS     0x05
#define CMD_CHIP_ERASE      0xC7
#define CMD_JEDEC_ID        0x9F

// -------------------------------------------------------
// Global State
// -------------------------------------------------------
uint16_t buf_a[BUF_SIZE];
uint16_t buf_b[BUF_SIZE];

int dma_chan_a = -1;
int dma_chan_b = -1;

volatile int buffer_ready = -1;     // -1 = none, 0 = A ready, 1 = B ready
volatile bool recording = false;
uint32_t flash_write_addr = 0;
uint32_t flash_read_addr = 0;
uint32_t recorded_length = 0;       // Total bytes recorded
volatile uint32_t overruns = 0;     // Buffers lost: the CPU was too slow
volatile bool flash_failed = false; // The flash chip stopped answering

// -------------------------------------------------------
// SPI Flash Driver
// -------------------------------------------------------
static inline void cs_select(void) {
    gpio_put(FLASH_CS_PIN, 0);
}

static inline void cs_deselect(void) {
    gpio_put(FLASH_CS_PIN, 1);
}

void flash_init(void) {
    spi_init(FLASH_SPI, 10 * 1000 * 1000);
    gpio_set_function(FLASH_SCK_PIN, GPIO_FUNC_SPI);
    gpio_set_function(FLASH_MOSI_PIN, GPIO_FUNC_SPI);
    gpio_set_function(FLASH_MISO_PIN, GPIO_FUNC_SPI);

    gpio_init(FLASH_CS_PIN);
    gpio_set_dir(FLASH_CS_PIN, GPIO_OUT);
    gpio_put(FLASH_CS_PIN, 1);
}

void flash_wait_done(void) {
    uint8_t cmd = CMD_READ_STATUS;
    uint8_t status;
    // A missing chip can read "busy" for ever; the slowest normal job,
    // a sector erase, takes at most 400 ms (W25Q32JV datasheet)
    absolute_time_t limit = make_timeout_time_ms(1000);
    do {
        cs_select();
        spi_write_blocking(FLASH_SPI, &cmd, 1);
        spi_read_blocking(FLASH_SPI, 0, &status, 1);
        cs_deselect();
        if (time_reached(limit)) {
            flash_failed = true;
            return;
        }
    } while (status & 0x01);
}

void flash_write_enable(void) {
    uint8_t cmd = CMD_WRITE_ENABLE;
    cs_select();
    spi_write_blocking(FLASH_SPI, &cmd, 1);
    cs_deselect();
}

void flash_sector_erase(uint32_t addr) {
    flash_write_enable();
    uint8_t cmd[4] = {
        CMD_SECTOR_ERASE,
        (addr >> 16) & 0xFF,
        (addr >> 8) & 0xFF,
        addr & 0xFF
    };
    cs_select();
    spi_write_blocking(FLASH_SPI, cmd, 4);
    cs_deselect();
    flash_wait_done();
}

void flash_page_program(uint32_t addr, const uint8_t *data, size_t len) {
    if (len > FLASH_PAGE_SIZE) len = FLASH_PAGE_SIZE;
    flash_write_enable();
    uint8_t cmd[4] = {
        CMD_PAGE_PROGRAM,
        (addr >> 16) & 0xFF,
        (addr >> 8) & 0xFF,
        addr & 0xFF
    };
    cs_select();
    spi_write_blocking(FLASH_SPI, cmd, 4);
    spi_write_blocking(FLASH_SPI, data, len);
    cs_deselect();
    flash_wait_done();
}

void flash_read_data(uint32_t addr, uint8_t *data, size_t len) {
    uint8_t cmd[4] = {
        CMD_READ_DATA,
        (addr >> 16) & 0xFF,
        (addr >> 8) & 0xFF,
        addr & 0xFF
    };
    cs_select();
    spi_write_blocking(FLASH_SPI, cmd, 4);
    spi_read_blocking(FLASH_SPI, 0, data, len);
    cs_deselect();
}

uint32_t flash_read_jedec_id(void) {
    uint8_t cmd = CMD_JEDEC_ID;
    uint8_t id[3];
    cs_select();
    spi_write_blocking(FLASH_SPI, &cmd, 1);
    spi_read_blocking(FLASH_SPI, 0, id, 3);
    cs_deselect();
    return (id[0] << 16) | (id[1] << 8) | id[2];
}

// Write a full buffer (BUF_BYTES) to flash, handling sector erases and page boundaries
void flash_write_buffer(const uint8_t *data, size_t total_len) {
    size_t written = 0;
    while (written < total_len) {
        uint32_t addr = flash_write_addr + written;

        // If we are at a sector boundary, erase the sector first
        if ((addr % FLASH_SECTOR_SIZE) == 0) {
            flash_sector_erase(addr);
        }

        // Calculate how many bytes we can write in this page
        size_t page_offset = addr % FLASH_PAGE_SIZE;
        size_t page_remaining = FLASH_PAGE_SIZE - page_offset;
        size_t chunk = total_len - written;
        if (chunk > page_remaining) chunk = page_remaining;

        flash_page_program(addr, data + written, chunk);
        written += chunk;
    }
    flash_write_addr += total_len;
}

// -------------------------------------------------------
// DMA Interrupt Handler
// -------------------------------------------------------
void dma_irq_handler(void) {
    if (dma_hw->ints0 & (1u << dma_chan_a)) {
        dma_hw->ints0 = 1u << dma_chan_a;   // Clear interrupt flag
        dma_channel_set_write_addr(dma_chan_a, buf_a, false);  // Rewind for next turn
        if (buffer_ready >= 0) overruns++;   // The last full buffer was never saved
        buffer_ready = 0;                    // Buffer A is full
    }
    if (dma_hw->ints0 & (1u << dma_chan_b)) {
        dma_hw->ints0 = 1u << dma_chan_b;   // Clear interrupt flag
        dma_channel_set_write_addr(dma_chan_b, buf_b, false);  // Rewind for next turn
        if (buffer_ready >= 0) overruns++;   // The last full buffer was never saved
        buffer_ready = 1;                    // Buffer B is full
    }
}

// -------------------------------------------------------
// ADC and DMA Setup
// -------------------------------------------------------
void adc_dma_init(void) {
    // Initialize ADC
    adc_init();
    adc_gpio_init(MIC_PIN);
    adc_select_input(0);  // ADC0 = GP26

    // Set sample rate: the ADC clock is 48 MHz and one conversion takes
    // 96 cycles (500 kHz maximum rate). With a divider, one conversion
    // starts every (1 + clkdiv) cycles of the 48 MHz clock.
    // For 8 kHz: 48000000 / 8000 = 6000 cycles, so clkdiv = 6000 - 1 = 5999
    float clkdiv = (48000000.0f / SAMPLE_RATE) - 1.0f;
    adc_set_clkdiv(clkdiv);

    adc_fifo_setup(
        true,   // Enable FIFO
        true,   // Enable DREQ
        1,      // DREQ asserted when at least 1 sample in FIFO
        false,  // No error bit
        false   // Keep full 12-bit samples (no 8-bit shift)
    );

    // Claim two DMA channels
    dma_chan_a = dma_claim_unused_channel(true);
    dma_chan_b = dma_claim_unused_channel(true);

    // Configure Channel A
    dma_channel_config cfg_a = dma_channel_get_default_config(dma_chan_a);
    channel_config_set_transfer_data_size(&cfg_a, DMA_SIZE_16);
    channel_config_set_read_increment(&cfg_a, false);
    channel_config_set_write_increment(&cfg_a, true);
    channel_config_set_dreq(&cfg_a, DREQ_ADC);
    channel_config_set_chain_to(&cfg_a, dma_chan_b);

    dma_channel_configure(dma_chan_a, &cfg_a,
        buf_a,              // Destination
        &adc_hw->fifo,      // Source
        BUF_SIZE,           // Transfer count
        false               // Don't start yet
    );

    // Configure Channel B
    dma_channel_config cfg_b = dma_channel_get_default_config(dma_chan_b);
    channel_config_set_transfer_data_size(&cfg_b, DMA_SIZE_16);
    channel_config_set_read_increment(&cfg_b, false);
    channel_config_set_write_increment(&cfg_b, true);
    channel_config_set_dreq(&cfg_b, DREQ_ADC);
    channel_config_set_chain_to(&cfg_b, dma_chan_a);

    dma_channel_configure(dma_chan_b, &cfg_b,
        buf_b,              // Destination
        &adc_hw->fifo,      // Source
        BUF_SIZE,           // Transfer count
        false               // Don't start yet
    );

    // Enable interrupts for both channels on IRQ0
    dma_channel_set_irq0_enabled(dma_chan_a, true);
    dma_channel_set_irq0_enabled(dma_chan_b, true);
    irq_set_exclusive_handler(DMA_IRQ_0, dma_irq_handler);
    irq_set_enabled(DMA_IRQ_0, true);
}

// -------------------------------------------------------
// Recording Control
// -------------------------------------------------------
void start_recording(void) {
    printf("Recording started...\n");
    recording = true;
    flash_write_addr = 0;
    recorded_length = 0;
    buffer_ready = -1;
    overruns = 0;

    gpio_put(LED_PIN, 1);   // LED on = recording

    // Drain any leftover ADC FIFO entries
    adc_fifo_drain();

    // Point both channels at the start of their buffers (a recording that
    // was stopped part way leaves the write addresses in the middle)
    dma_channel_set_write_addr(dma_chan_a, buf_a, false);
    dma_channel_set_write_addr(dma_chan_b, buf_b, false);

    // Start Channel A, which will chain to B when done
    dma_channel_start(dma_chan_a);
    adc_run(true);
}

void stop_recording(void) {
    adc_run(false);
    adc_fifo_drain();

    // Abort both DMA channels
    dma_channel_abort(dma_chan_a);
    dma_channel_abort(dma_chan_b);

    recorded_length = flash_write_addr;
    recording = false;
    buffer_ready = -1;
    gpio_put(LED_PIN, 0);   // LED off

    printf("Recording stopped. %u bytes stored, %u buffers lost.\n",
           (unsigned)recorded_length, (unsigned)overruns);
}

// -------------------------------------------------------
// PWM Playback
// -------------------------------------------------------
void pwm_audio_init(void) {
    gpio_set_function(PWM_PIN, GPIO_FUNC_PWM);
    uint slice = pwm_gpio_to_slice_num(PWM_PIN);
    uint channel = pwm_gpio_to_channel(PWM_PIN);

    // Configure PWM for audio output
    // Wrap at 4095 to match 12-bit ADC range
    pwm_set_wrap(slice, 4095);
    pwm_set_chan_level(slice, channel, 0);
    pwm_set_enabled(slice, true);
}

void play_recording(void) {
    if (recorded_length == 0) {
        printf("No recording to play.\n");
        return;
    }

    printf("Playing back %u bytes...\n", (unsigned)recorded_length);
    gpio_put(LED_PIN, 1);

    uint slice = pwm_gpio_to_slice_num(PWM_PIN);
    uint channel = pwm_gpio_to_channel(PWM_PIN);

    uint8_t page_buf[FLASH_PAGE_SIZE];
    uint32_t addr = 0;
    absolute_time_t next = get_absolute_time();

    while (addr < recorded_length) {
        size_t chunk = recorded_length - addr;
        if (chunk > FLASH_PAGE_SIZE) chunk = FLASH_PAGE_SIZE;

        flash_read_data(addr, page_buf, chunk);

        // Output samples via PWM
        for (size_t i = 0; i + 1 < chunk; i += 2) {
            uint16_t sample = page_buf[i] | (page_buf[i + 1] << 8);
            sample &= 0x0FFF;  // Mask to 12 bits
            pwm_set_chan_level(slice, channel, sample);

            // Wait until the next sample is due: 125 us after the last one
            // was due, so the flash reads do not slow the playback down
            next = delayed_by_us(next, 125);
            sleep_until(next);
        }

        addr += chunk;
    }

    // Silence output after playback
    pwm_set_chan_level(slice, channel, 0);
    gpio_put(LED_PIN, 0);
    printf("Playback complete.\n");
}

// -------------------------------------------------------
// Button Handling
// -------------------------------------------------------
void button_init(void) {
    gpio_init(BUTTON_PIN);
    gpio_set_dir(BUTTON_PIN, GPIO_IN);
    gpio_pull_up(BUTTON_PIN);
}

bool button_pressed(void) {
    static bool last_state = true;  // Pull-up: idle = high
    static uint32_t debounce_time = 0;

    bool current = gpio_get(BUTTON_PIN);

    if (current != last_state) {
        if (time_us_32() - debounce_time > 200000) {  // 200 ms debounce
            debounce_time = time_us_32();
            last_state = current;
            if (!current) {  // Button pressed (active low)
                return true;
            }
        }
    }
    return false;
}

// -------------------------------------------------------
// Main
// -------------------------------------------------------
int main(void) {
    stdio_init_all();
    sleep_ms(2000);  // Wait for USB serial to connect

    printf("=== RP2040 Audio Sampler ===\n");

    // Initialize LED
    gpio_init(LED_PIN);
    gpio_set_dir(LED_PIN, GPIO_OUT);
    gpio_put(LED_PIN, 0);

    // Initialize peripherals
    button_init();
    flash_init();
    pwm_audio_init();
    adc_dma_init();

    // Verify flash chip
    uint32_t jedec_id = flash_read_jedec_id();
    printf("Flash JEDEC ID: 0x%06X\n", (unsigned)jedec_id);
    if (jedec_id == 0x000000 || jedec_id == 0xFFFFFF) {  // A W25Q32 gives 0xEF4016
        printf("WARNING: Flash not detected. Check wiring.\n");
    }

    printf("Press button to start/stop recording.\n");
    printf("Press and hold for 1.5 s to play back.\n");

    uint32_t press_start = 0;
    bool held = false;

    while (true) {
        // Handle button presses
        if (button_pressed()) {
            press_start = time_us_32();
            held = false;
        }

        // Detect long press for playback (button held > 1.5 seconds)
        if (!gpio_get(BUTTON_PIN) && press_start != 0 && !held) {
            if (time_us_32() - press_start > 1500000) {
                held = true;
                if (!recording) {
                    play_recording();
                }
                press_start = 0;
            }
        }

        // Short press toggles recording
        if (gpio_get(BUTTON_PIN) && press_start != 0 && !held) {
            if (time_us_32() - press_start > 50000) {  // Debounce
                if (recording) {
                    stop_recording();
                } else {
                    start_recording();
                }
                press_start = 0;
            }
        }

        // Process completed DMA buffers during recording
        if (recording && buffer_ready >= 0) {
            int buf_idx = buffer_ready;
            buffer_ready = -1;

            uint8_t *data;
            if (buf_idx == 0) {
                data = (uint8_t *)buf_a;
            } else {
                data = (uint8_t *)buf_b;
            }

            // Check if we have space in flash
            if (flash_write_addr + BUF_BYTES > FLASH_MAX_ADDR) {
                printf("Flash full!\n");
                stop_recording();
                continue;
            }

            // Write the completed buffer to flash
            flash_write_buffer(data, BUF_BYTES);
            if (flash_failed) {
                printf("Flash not responding. Check wiring.\n");
                flash_failed = false;
                stop_recording();
            }
        }

        tight_loop_contents();
    }

    return 0;
}
```

## How It Works

<InArticleAd />


This is what happens during one recording, in order:

<Steps>
1. You press the button. `start_recording()` empties the ADC FIFO, starts DMA Channel A, and starts the ADC in free-running mode.
2. The ADC converts one sample every 125 microseconds. Each result goes into the ADC FIFO, and the ADC raises DREQ_ADC.
3. For each request, Channel A reads 16 bits from the ADC FIFO register and writes them to the next place in `buf_a`. The read address stays fixed; the write address moves forward by 2 bytes.
4. After 1024 transfers `buf_a` is full. The hardware raises the interrupt DMA_IRQ_0 and starts Channel B through `chain_to`.
5. Channel B takes the next sample and writes into `buf_b`. No sample is lost.
6. The interrupt handler points Channel A back to the start of `buf_a` for its next turn and sets `buffer_ready = 0`, which tells the main loop that `buf_a` is full.
7. The main loop sees `buffer_ready == 0` and writes the 2048 bytes of `buf_a` to the flash: eight pages of 256 bytes, with a sector erase first at every 4 KB boundary.
8. Meanwhile Channel B fills `buf_b`. The CPU finishes with `buf_a` before `buf_b` is full.
9. Channel B finishes, raises the interrupt, and starts Channel A. The cycle continues.
10. You press the button again. `stop_recording()` stops the ADC, stops both DMA channels, and stores the total number of bytes.
</Steps>

The one rule the design must keep: the CPU must finish with one buffer before the other is full. A buffer fills in 128 ms; the page writes take about 6 ms, plus a sector erase of about 45 ms for every second buffer, so the longest typical job is about 51 ms, leaving about 77 ms. These are typical values. The datasheet maximum for a sector erase is 400 ms, longer than a whole buffer, so a recorder that must never lose a buffer erases its sectors before the recording starts. The firmware does not hide a late CPU: the interrupt handler counts a buffer as lost when it finds the previous full buffer still unsaved, and `flash_wait_done()` gives up after 1 s, so a missing or loose flash chip stops the recording with a message instead of freezing the Pico.

### Check it

1. At start the serial monitor shows `Flash JEDEC ID: 0xEF4016` for a W25Q32. 0x000000 or 0xFFFFFF means no answer from the chip: check the four SPI wires.
2. Record for 10 s by a clock. Only full buffers are saved (the part-filled one is dropped at stop), so expect 78 buffers: `159744 bytes stored, 0 buffers lost`. Any lost buffers mean the flash was too slow for this rate.
3. Play it back and time it: it must also take about 10 s. Whistle a steady note while recording, then compare the note of the playback with a phone tuner; a lower note means the playback runs slow.

:::tip[Instrument it]
This is exactly the machinery a real vibration monitor needs. Bearing and gear faults live in the kilohertz range, and catching them means sampling an accelerometer fast and continuously without dropping a window, which is what DMA ping-pong buffering gives you: one buffer fills from the ADC while the other is processed or flushed to flash. Stream an ADXL1002 or a digital accelerometer through this pipeline, run an FFT, and a Pico becomes a condition monitor that [reports the spectrum](https://siliconwit.io) the moment a fault tone rises.
:::

## Experiments

<InArticleAd />


Four changes to try on the working recorder:

<CardGrid>
<Card title="1. Increase the Sample Rate" icon="pencil">
Change the sample rate from 8 kHz to 16 kHz or even 44.1 kHz with the ADC clock divider (`adc_set_clkdiv`). The buffers then fill faster, so check that the flash writes still finish in time. At 44.1 kHz, each 1024-sample buffer fills in about 23 ms. That is enough for the eight page writes (about 6 ms) but not for a 45 ms sector erase, so erase the sectors before recording starts or use larger buffers. Monitor the serial output to confirm no buffers are missed.
</Card>
<Card title="2. Add Simple Compression" icon="pencil">
The 12-bit samples are stored as 16-bit values, wasting 4 bits each. Compress them to 4 bits per sample with ADPCM (Adaptive Differential Pulse Code Modulation), for 4 times the recording time of the 16-bit storage. The IMA ADPCM algorithm encodes the differences between consecutive samples with a step table and an index. Compress in the main loop before writing to flash, and decompress during playback.
</Card>
<Card title="3. Use DMA Pacing Timer Instead of ADC Clock Divider" icon="pencil">
Run the ADC at its maximum rate and let one of the four DMA pacing timers (TREQ values 0x3B through 0x3E) limit the DMA transfers to 8 kHz. Compare the sample timing with an oscilloscope, or record a tone of known frequency and check the playback pitch.
</Card>
<Card title="4. Add a Recording Index" icon="pencil">
Reserve the first 4 KB sector of flash as a directory of the start address, length and timestamp of each recording, so you can store several and choose one to play. Extend the button: single press to record, double press to play the latest clip, long press to play the next stored clip.
</Card>
</CardGrid>
